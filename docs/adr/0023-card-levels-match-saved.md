# 0023 圖卡闖關：配對完成存進選填的 settings.cardsMatched，三顆星只在一處導出

狀態：採用
日期：2026-11-27

## 背景

考生自己用 Gemini 做了一頁式的刷題頁，資料不可靠，但答題的流程她很滿意：每個考點是一關，關卡裡依序「看圖記憶 → 圖像配對（連連看）→ 情境實戰」，關卡清單上有三顆星（`docs/plans/level-mode.md` §1）。我們的漫畫、卡片原文、官方題都比較可靠，缺的是這個流程。使用者 2026-11-27 選定：實戰留在關卡頁裡答、星星要記住配對完成（要新增存檔欄位）。

0022 寫了「練習（遮起來想、排一排）的成績不存」，本份部分取代它：配對完成改成存卡片 ID。配對完成要讓第二顆星重新開 App 還在、跨裝置一致，只能存。

## 決定

- 新增選填欄位 `settings.cardsMatched?: string[]`：配對全部做對過的卡片 ID，只增不減。做法逐處比照 `settings.cardsSeen`：指令 `markCardMatched`、存檔驗證、同步檔選填的 `cardsMatched`，合併取聯集（交換律、舊同步檔沒有這欄視為空）。配對的過程（點錯幾次、花多久）不存。
- 三顆星只在 `src/systems/cardStars.ts` 導出（selector 轉出）：
  - 看過：`cardsSeen` 有這張。
  - 配對：`cardsMatched` 有這張；沒有漫畫的卡沒有這顆。
  - 實戰：這張卡連到的官方題每一題的 `Progress.correct ≥ 1`；沒有連到題的卡沒有這顆。
  - 一張卡有幾顆星＝它有幾個步驟；畫面只顯示它有的星，不畫灰的空位。
- 連連看由漫畫資料機械產生（`src/systems/comicMatch.ts`，純函式，給亂數就固定）：左邊是格子的圖（字與舉牌遮住，`label` 留著），右邊是打亂的格子說明。判對錯比說明的字串，兩格字相同互通。不新寫任何內容。
- 實戰用官方題，照常走 `startCardRound` 與作答紀錄；不出模型自己寫的題。

## 放棄的做法

- 第二顆星不存、每次開 App 歸零：她要的是闖關的累積感，歸零等於沒有星。
- 存每關的星數或分數：星星能從三個來源導出，存了就有兩份事實。
- 照搬她那頁的情境題：題目是模型寫的，沒有來源，違反「題庫只來自考選部官方 PDF」。

## 後果

- `persistenceGolden.test.ts` 新增一份含 `cardsMatched` 的樣本，舊樣本不改；舊版 App 讀到有這欄的存檔會照常（未知欄位忽略），同步時舊版那台寫回會暫時蓋掉這欄，更新後下次同步補回（同 0013 的 `cardsSeen`）。
- 第三顆星沿用作答紀錄：在刷題頁答對過那幾題也算，不必在關卡裡答。
