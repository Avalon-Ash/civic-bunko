# 圖卡架構圖重畫（樹狀圖、表格）

- 開案：2026-11-28，主席（Opus 5.5）。決策 ADR 0025。
- 起因：考生回饋（使用者轉述）說圖卡最大的問題是架構圖簡化過頭。
- 期限：12-02 起只修錯，所以 12-01 前併入。
- 狀態：2026-11-28 全部併入上線。CD1、CD2 由 agy Orchestrator（Neon）畫，主席讀過 53 張、對照條文與卡片原文；改了一處（五院表格行政院那列：原本寫成像在說政務委員由總統任命，改成「院長由總統任命」）。320 寬量過 57 張不溢出；4 張樹狀圖比一個手機畫面略高（700–750px）。

## 1. 現況
57 張卡的 `visual` 只有流程與對照兩種，大多只畫一面的一行摘要。例如「法律位階」只有「憲法 → 法律 → 命令」，「中央與地方」只有自治與委辦的兩欄對照。

## 2. 做法
- **引擎**（主席做完，2026-11-28）：多兩種形狀。
  - `tree`：層級與分流，線上可寫「30 日內」這類字，節點可帶補充小字。
  - `table`：同一件事在各層級怎麼做。
  - 檢查只在 `systems/cardVisual.ts`；畫法在 `kit/Visual.tsx`。
- **樣張 4 張**（主席做，條文逐條對過）：
  - 法律位階（樹）
  - 中央與地方（樹：直轄市、縣、市、省各層）
  - 訴願到行政訴訟（樹：兩條路）
  - 自治監督（表：三個層級 × 違法撤銷、代行處理、停職解職）

## 3. 怎麼選形狀
- **有上下層、有分支**（位階、層級、組織、救濟的路）→ `tree`。
- **同一件事比較 3 個以上對象**，或比較 2 個以上面向 → `table`。
- **真的是一條順序**（政策五階段、預算演進）→ 保留 `flow`，但要補上每一步的重點（`note` 放不進 flow，就改成 tree 一條直鏈）。
- **兩個概念正面對照、各 2–3 點**就講完 → 保留 `versus`。
- 一張圖要涵蓋整張卡的架構，不是只畫一面。

## 4. 內容規則
- 圖上的每個事實都要能在該卡的 `faces` 或 `lawRefs` 指到的 `data/laws` 條文裡找到；條文沒寫的通說要跟卡片原文一致。
- 不改 `faces`、`hook`、`comic`、`questions`，只改 `visual`。
- 紅框（`hot`）只給問法陷阱，粗框（`key`）要有 `legend` 說明。
- 驗收：`npm run validate`、`npm test`、`npm run lint`、`npm run build` 全過；主席抽 10% 對條文；看 390／320 寬截圖。
