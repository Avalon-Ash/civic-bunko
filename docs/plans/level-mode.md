# 圖卡闖關（看圖 → 配對 → 實戰）

- 開案：2026-11-27，主席（Opus 5.5）。決策 ADR 0023。上游：`docs/plans/comic-cards.md`（漫畫）、`docs/plans/ux-cleanup.md`（列表的 `badge` 位置）。
- 狀態：動工中。

## 1. 為什麼
考生自己用 Gemini 做了一頁式刷題頁（使用者 2026-11-27 分享）。那頁的資料是模型寫的、不可靠，但她對**答題流程**很滿意，而且她自己說不清楚要什麼，看到這頁才說「就是這個」。那頁的流程是：
- 關卡清單（依科目篩選），每關三顆星。
- 進到一關，上面三個分頁依序走：1 看圖記憶 → 2 圖像配對 → 3 情境實戰。
- 配對：先點左邊的線索、再點右邊的名詞；對了兩個一起變綠、計數 1/4；錯了跳一句「差一點！回想一下剛剛那張插畫」，不扣分。
- 實戰：題目在同一頁答，答對當場說「答對了」。

我們有比較可靠的資料（漫畫只能指向卡片原文、官方題），缺的是這個流程。

## 2. 做法
| 她那頁 | 我們 |
| :-- | :-- |
| 關卡清單＋星星 | 圖卡頁「漫畫」篩選的列表，每張卡在 `badge` 位置顯示它有的星 |
| 1 看圖記憶 | 漫畫＋遮起來想（`ComicSection`），下面是完整文字 |
| 2 圖像配對 | 連連看：左邊是漫畫格（字與舉牌遮住、`label` 留著），右邊是打亂的格子說明；點左再點右（或反過來），對了變綠鎖住，錯了兩邊抖一下＋一句提示，不扣分；全對記 `markCardMatched` |
| 3 情境實戰 | 這張卡的官方題，留在關卡頁裡答（沿用 `startCardRound` 與題目元件），答完當場顯示幾題對 |
| 星星 | 看過、配對、實戰，只在 `systems/cardStars.ts` 導出（ADR 0023） |

不照搬：模型寫的情境題（只用官方題）、RPG 外殼（XP、等級、魔王；App 已有小魚乾、集章、小貓）。

## 3. 切三段，每段可單獨上線
12-02 起只修錯、不加功能，所以每段做完驗收就推。

| 段 | 內容 | 做不完的退路 |
| :-- | :-- | :-- |
| L1 連連看 | `systems/comicMatch.ts`＋測試、`ComicMatch` 元件，先放進現有抽屜（漫畫下面一顆「配對」） | — |
| L2 存檔與星星 | `settings.cardsMatched`（指令、存檔驗證、同步聯集、golden 新樣本）、`cardStars`、列表 `badge` 顯示星星 | 星星只顯示看過與實戰 |
| L3 關卡頁 | 有漫畫的卡打開是關卡頁：三個步驟分頁；第 3 步內嵌作答 | 11-30 收工還不穩：第 3 步退回「刷這張卡的題」按鈕 |

## 4. L3 動手前要解決的
- 已有回合（含模擬考）進行中：第 3 步不開新回合，只說「先把刷題那回合做完」。
- `App.tsx` 在回合結束時設 `showResult`：關卡裡答完不能讓刷題頁之後跳出不相干的結果頁。「這回合來自哪張卡的關卡」放記憶體（不存檔）。
- 切分頁會卸載 `CardsScreen`：回到圖卡頁時，若有關卡來的回合還在進行，直接回到那一關的第 3 步。
- 關卡頁裡答完的解析區不顯示「圖卡：…」（會指回自己）。
- 什麼算「看過」：關卡頁的看圖步驟裡，翻完完整文字照舊 `markCardSeen`；另外配對全對也算看過（她已經認真看過圖了）。
- `cards-unseen` 落點仍只標一次。
