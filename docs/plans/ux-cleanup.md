## 2. 任務引導：叫法與目的地

### 2.1 叫法（顯示字改、存檔鍵不改）

「任務」只留給一套。預設方案（叫法本身由使用者決定，§8-1）：

| 現在的叫法 | 是什麼 | 改叫 | 理由 |
| :-- | :-- | :-- | :-- |
| 今日任務 | 每天一個、給小魚乾（`QUESTS`） | **今日任務**（不變） | 完成提示、小貓頁都已經這樣叫 |
| 今天的 3 個小任務 | 每科 5 題，三回做完蓋章 | **今天的 3 回快刷** | 它其實是三顆「開始」鈕，不是要去別處完成的任務 |
| 今天刷了 N 題＋5／15／30 題 | 當天題數到了就給小魚乾 | **題數獎勵** | 和上面兩套分開 |

只改畫面上的字。`QuestId`、`MISSION_SIZE`、`DAILY_GOAL_QUESTIONS` 這些名稱與存檔鍵不動；已發出的更新紀錄不回頭改。

### 2.2 目的地表（只定義在一處）

- **任務的目的地寫在任務自己身上**：`QUESTS` 每一列加 `go`（`src/core/constants/wardrobe.ts`）。`Quest` 型別多一個必填的 `go`，新增任務種類沒填目的地 `tsc` 就紅。`QUESTS` 不進存檔（存的是 id），加欄位不影響她的資料。
- **其他「被叫去做事」的目的地**放一張表 `src/core/constants/guide.ts`：成就用 `Record<AchievementMetric, GuideTarget>`，其餘用具名的一列。型別 `GuideTarget`、`GuideAnchor` 放 `src/core/types.ts`；`TabId` 現在定義在 `src/ui/kit/TabBar.tsx`，要搬進 `types.ts`（型別只定義在一處，ADR 0005）。
- **畫面只經一個入口換頁**：`App.tsx` 的四個回呼收成一個 `go(target)`。`target` 是「哪個分頁＋落在哪個錨點＋要不要預選」。
- **錨點**：目標元素標 `data-guide="<錨點 id>"`。`go()` 換頁後把它捲進畫面、閃一下（純 CSS，尊重減少動態）。錨點 id 的清單只在 `guide.ts`。

**有回合正在進行時**：刷題分頁顯示的是題目頁，設定頁不存在（`App.tsx:245–262`）。規則：目的地在刷題分頁而她有還沒做完的回合，就只換到刷題分頁（回到那一題），不落點、不預選、不清掉回合；那一回做完本來就可能完成任務。停在結果頁時先收掉結果頁再落點（現在的 `onGoSetup` 就是這樣，`App.tsx:220–223`；回合已經結束，沒有東西會丟）。

**錨點還沒掛上時**：`go()` 找不到錨點就只換分頁，不報錯。UX1a 上線當晚多數錨點還不存在，這是預期的過渡。

「直接開始」只保留已經是這樣的今日頁三回快刷。其他一律「落在按鈕」：範圍、題數是她自己設的，替她按下去會開出她沒選的回合。

### 2.3 驗收：從今日頁到完成按鈕點幾下

標準（前提：沒有進行中的回合）：**點任務卡 1 下，完成它的那顆按鈕就在畫面裡**（模擬考是選卷抽屜打開）。下一下就是開始。現況是 1 下到小貓頁，之後要自己找分頁、找按鈕。

量法（兩層）：
- **機器**（進 `npm test`）：`guide.test.ts` 檢查 (a) 每個目的地用到的錨點 id 都在清單裡；(b) 掃 `src/ui/**/*.tsx`：畫面上標的 `data-guide` 都在清單裡、同一個 id 不標兩次（UX1a 就開）；「清單裡每個 id 都有人標」這一半到 UX5 才開（各畫面要到 11-30 才全部併入，提早開會讓 `main` 紅三天）；(c) 每個 `QuestKind`、每個 `AchievementMetric` 都有目的地（型別已保證，測試再守一次清單不是空的）。fixture 從 `QUESTS`、`ACHIEVEMENTS` 取，不寫死 id。錨點清單與目的地表由主席在 UX1a 一次放齊，之後的包只在畫面上標 `data-guide`，不改 `guide.ts`。
- **主席在預覽裡**：照 §2.2 的表逐列點，記「點完後錨點元素的 `getBoundingClientRect()` 是否完全在視窗內」。390×844，空白存檔與有資料的存檔各一次。任務種類用開發機改日期或暫時改挑選結果來輪，不改正式程式。

## 3. 資訊架構：改前改後

原則：**不搬分頁、不搬主要入口**。只做收合、換順序、預設少顯示。五個底部分頁與順序不變；開始刷、三回快刷、模擬考的位置不變。

| 分頁 | 現在（由上而下） | 改後 | 目標高度（390×844、空白存檔） |
| :-- | :-- | :-- | :-- |
| 今日 | 倒數 → 完成度 → 加到主畫面 → 今日任務 → 3 個小任務 → 這週的章 → 音效 → 天氣 → 更新／版本 | 前六塊順序不變（任務卡點了去對的地方；小任務改叫 3 回快刷）；**音效、天氣、更新／版本收成一列「設定」，原地、預設收起** | ≤ 1,150px（現 1,417；估：減三塊設定 393、加一列約 60） |
| 圖卡 | 分類 → 科目篩選 → 33 張全攤開 | 分類與篩選不變；**列表變矮**（做法二選一，UX0 截圖後定，§8-4）；有漫畫的卡多一格小圖、多一顆「漫畫」篩選（漫畫案 §3-1，由本案的 UX3 做，見 §6） | 預設狀態 ≤ 2,000px（現 4,664） |
| 刷題 | 模擬考 → 弱點＋高頻 → 怎麼刷 → 題數 → 科目 → 題型 → 出題模式 → 選項打亂 → 開始刷 | 前五塊不變；**題型、出題模式、選項打亂收成「更多設定」**，預設收起，收起時用一行字寫出目前的選擇；開始刷維持黏在底部 | ≤ 1,000px（現 1,303），且開始刷在首屏看得到 |
| 小貓 | 小屋 → 擺設 → 名牌列 → 取名／陪我刷題／帶出門 → 題數與任務 → 試衣間 → 部位篩選 → 配件格（全部）→ 成就 | 結構不變；**配件格預設只顯示一個部位**（部位籤本來就有，只是預設值從「全部」改成第一個部位，「全部」還在）。成就區不動：它本來就只顯示前 3 個還沒解鎖的（`WardrobeScreen.tsx:36`、`:232`），而且每張成就卡都是小貓的落腳點（`:557` 的 `data-cat-perch`），再收起來省不到多少、落腳點卻只剩一張 | ≤ 2,400px（現 4,435；估，配件格一個部位多高要 UX0 量） |
| 集章 | 我的章 → 弱點 → 高頻 → 各科進度 → 同步與備份 → 版本 | 順序不變；**同步與備份預設收成一列（顯示同步狀態）**，出錯或被引導來時自動展開；各科進度不收（那是她來這頁要看的） | ≤ 1,350px（現 1,751；估） |

- 目標數字都是估的：稽核基準是 375×812，驗收用 390×844。**UX0 用同一個量測片段在 390×844 重量一次基準**，目標改成「基準的幾成」再開工，不拿兩種尺寸互比。
- 收合用一個新的 kit 元件 `src/ui/kit/Collapse.tsx`（標題列＋`aria-expanded`＋內容）。集章頁高頻考點現有的收合（`StampsScreen.tsx:152`）改用它；小貓頁成就的「看全部」是切換清單不是收合，不動。
- **設定集中成一頁、同步搬家：排考後**（UX6）。那是換位置，她考前幾天不該重新找東西；考前只做「原地收起」。
- 小貓頁分成「小屋／衣櫥／成就」三層：排考後（UX6）。它不影響刷題，結構又和試衣間黏住的設計綁在一起。

## 4. 量測（可重跑）

repo 沒有瀏覽器自動化的依賴，不為這件事加。量測是一段固定的片段，主席在預覽（`.claude/launch.json` 的 `civic-bunko`）裡執行；UX0 把它定稿存成 `tools/ux/measure-tab.js`（不進 build），之後每包都跑同一份。

```js
// 草稿：捲動容器是 .cb-main（src/ui/styles/base.css:15）。回傳目前分頁的高度、幾個螢幕、看得到的按鈕數、直屬區塊。
(() => {
  const main = document.querySelector('.cb-main');
  const box = main.firstElementChild;
  return {
    viewport: [innerWidth, innerHeight],
    scrollHeight: main.scrollHeight,
    screens: +(main.scrollHeight / innerHeight).toFixed(1),
    buttons: main.querySelectorAll('button:not([disabled])').length,
    blocks: [...box.children].map((el) => [Math.round(el.getBoundingClientRect().height), el.textContent.trim().slice(0, 12)]),
  };
```
