# 開案書：小八喵衣櫥（紙娃娃＋小魚乾＋任務與成就）

- 開案：2026-11-17，主代理 Opus 5.5（Fable 留給美術兩次失敗後接手與終審）。使用者已同意設計方向。
- **期限**：本週（11-22 前）全部上線。12-02 起只修錯。
- 一句話：用收集換裝，讓她每天多刷幾題。

## 1. 目標
- 小貓可以分部位換裝（像 RO 的頭飾上／中／下＋披風），一次穿多件。
- 刷題賺「小魚乾」，在衣櫥商店換衣服、飾品、毛色、背景。
- 每天有固定的題數關卡和一個輪替的小任務；成就一次性給小魚乾或專屬配件。
- **給得大方、門檻低**（使用者 11-17：「太多門檻會變成上班」）。不做抽卡、不做體力、不做會掉的東西。

## 2. 不能破壞的東西
- 她的進度：`AGENTS.md` §2「使用者資料」。新狀態全部放在選填欄位 `Settings.wardrobe`，缺欄位有預設、壞資料只丟那一欄。
- **舊版 App 讀到不認得的配件 ID 會讓整份存檔讀取失敗**（`persistence.ts` 的 `isValidSettings` → `Invalid settings object`）。所以新配件**不准寫進 `settings.accessory`**；它維持只放舊 6 件。換裝寫在 `wardrobe.outfit`。
- 舊 6 件的 ID 與「每 3 章解鎖 1 件」規則不變，她已經拿到的照樣有。
- 配件、成就、任務的 ID 產生後不改名、不重編（跟題目 ID 一樣是使用者資料的鍵）；已發佈的價格與獎勵不改（改了會讓餘額變動）。

## 3. 架構

### 3.1 部位（紙娃娃）
參考 RO：角色拆成獨立部位，疊圖順序寫在一張表。小八喵是一整塊圓身體，全身一起動，所以不需要每格的對位點；配件直接畫在貓的 64×64 座標裡。以後有「頭跟身體分開動」的姿勢再加對位點表。

| 部位 `SlotId` | 疊圖（下→上） | RO 對應 | 舊配件 |
| :-- | :-- | :-- | :-- |
| `bg` 背景 | 1（貓後面） | — | |
| `back` 背飾 | 2（貓後面） | 披風 | |
| （貓本體） | 3 | 身體＋頭 | |
| `body` 身上 | 4 | 鎧甲 | |
| `neck` 頸 | 5 | — | 圍巾 |
| `face-low` 臉下 | 6 | 頭飾下 | |
| `face-mid` 臉中 | 7 | 頭飾中 | 圓眼鏡 |
| `head-side` 頭側 | 8 | — | 蝴蝶結、小花 |
| `head-top` 頭頂 | 9 | 頭飾上 | 草帽、皇冠 |
| `fur` 毛色 | 不是圖層：換 `--cat-fur` 等色票 | 染色 | |

- 部位與順序只定義在 `src/core/constants/wardrobe.ts` 的 `SLOTS`；配件清單（ID、部位、名稱、取得方式）只定義在同檔 `ITEMS`。
- 配件的圖只在 `src/ui/kit/wardrobe/`（每件一個 SVG 片段，以 ID 查）；`Cat` 依 `SLOTS` 順序疊圖。毛色是 `src/theme.css` 的色票組。
- 素材：找過 CC0（Kenney、OpenGameArt、Open Peeps），沒有跟小八喵畫風相符的貓咪換裝素材 → 主代理自己畫 SVG。兩次畫不好就交 Fable；再不行改走使用者的 3D 烘焙流程。

### 3.2 小魚乾（不存餘額，只存來源）
餘額 ＝ 賺到的 − 已買配件的價格總和。

賺到的（全部從「只會變多」的資料算，兩台裝置合併時取聯集或較大值，不會互蓋）：
- `WARDROBE_START_DAY` 起每天的題數（`dayLog`，作答與看答案都算）× 每題 1 條；
- 每日題數關卡（5、15、30 題）各給一次；
- 見面禮一次；
- 已解鎖的成就各自的獎勵（`wardrobe.achievements`，聯集）；
- 已完成的每日小任務（`wardrobe.quests`，以日期為鍵、取聯集）。

已買的配件：`wardrobe.owned`（聯集）。同一筆錢在兩台離線各花一次，合併後餘額可能是負的：畫面顯示 0、買不了東西，賺回來就好，不另外處理。

### 3.3 每日小任務
每天一個，從任務池用日期決定（兩台同一天抽到同一個）；做到就自動記下並給小魚乾。任務都是「學習動作」：完成一回作答、錯題重做一回、弱點或高頻回合一回、看一張新圖卡、交一份模擬考。

### 3.4 成就
條件全是累計值（總題數、熟練題數、章數、連續蓋章天數、看過的卡片、模擬考），上線當天依她既有的紀錄補算。解鎖後記在 `wardrobe.achievements`，之後條件就算因為合併變小也不收回。

### 3.5 同步
- 同步檔加選填的 `wardrobe: { owned, achievements, quests }`，全部取聯集；舊版同步檔沒有這欄照常可讀。
- `outfit`（目前穿什麼）和舊的 `accessory` 一樣只存在各裝置，不同步。

## 5. 驗收
- `npm run lint`、`npm run validate`、`npm test`、`npm run build` 全過；主程式 JS 大小照 §5 的上限。
- 守門：`src/systems/persistenceGolden.test.ts` 與 `src/testing/golden/**` 不動；新增一份帶 `wardrobe` 的樣本與測試。
- 測試要涵蓋：舊存檔（只有 `accessory`）讀進來穿著不變；舊版同步檔（沒有 `wardrobe`）合併不丟資料；兩份 `wardrobe` 合併結果與順序無關；餘額公式；成就補算；每日任務兩台抽到同一個。
- 畫面：390×844、820×1180、日夜兩套截圖；換裝每一件都要看過。

## 6. 什麼時候停下來問
- 要改既有存檔欄位的意義、或要寫遷移。
- 價格或獎勵上線後要改。
- 美術兩次不及格（交 Fable 前先說）。
