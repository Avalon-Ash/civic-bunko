# CC0：四格漫畫圖卡模式 開案（交 Fable）

## 目標
替 civic-bunko 開一份「四格漫畫圖卡」新模式的開案書，寫到 `docs/plans/comic-cards.md`。只寫開案書，不寫程式、不改其他檔。

## 真正的需求
App 唯一的使用者（考生）說現在的圖卡很難背。她要用四格漫畫的起承轉合，讓「印象」和「硬背」同步。原始需求、主代理的判讀、規格條目對到既有卡片的對照表，都在 `docs/reference/comic-cards-request.md`，先讀完它。

那份 RPG 規格是 AI 依她的口述產生的。裡面的 RPG 外殼、經驗值、圖鑑收集、錯題、魔王關、弱點分析、歷次成績，App 大多已經有了（刷題、模擬考、弱點回合、集章、小貓衣櫥的小魚乾）。請把這些對應到既有功能，不要另蓋一套；真的缺的才列成新包。

## 限制（要守的事）
1. **時間**：今天 2026-11-26，考試 12-05，12-02 起只修錯。可開發的日子是 11-27 到 12-01。請給切線：只做 2 天時上線什麼、做滿 5 天時上線什麼。第一包必須是她當天就用得到的垂直切片（幾張卡從頭到尾能用）。
2. **美術是最大風險**：repo 現有的插畫能力只有小貓的 SVG（`src/ui/kit/CatBody.tsx`、`petShape.ts`、`kit/wardrobe`）。請選一種 5 天內量產得完的畫法，並說明理由。量產前要有樣張關卡：先做 2–3 張不同型的卡（例如時間軸型、對比型、階層型）給使用者和她看過再量產。造形被退一次就停下來要參考圖，不憑文字猜著重畫。照一般人的卡通印象畫，不追求結構正確。
3. **內容**：格子裡的字只能出自既有卡的 `hook`、`faces`、`lawRefs`；規格和卡不一致時以卡為準（卡已對過 `data/laws`），規格裡的數字不當內容來源。規格沒列但 App 有的卡也要排進計畫（可以排在後面的切線）。
4. **小遊戲**（看圖記憶、圖像配對、情境選擇、間隔複習）：題目由卡片資料機械產生，同一份內容不寫兩次。情境題用既有的官方題掛到卡上，不新寫考題（題庫只來自考選部 PDF）；你認為這條要鬆綁，寫成給使用者的提案。
5. **卡片和考點沒有連結**：題目解析頁看不到對應的圖卡（「看到考題想起圖片」的缺口）。請決定要不要補、怎麼補、放在哪個切線。
6. **存檔與同步**：她已經在用、有同步。新狀態只能是加法欄位，要過 `src/systems/persistenceGolden.test.ts`；要同步就要有可交換的合併規則（ADR 0013），或改由既有作答紀錄導出、不存新欄位。資料放 pack、畫法放引擎（ADR 0011）。
7. **不新增耦合**：一個概念的性質只定義在一處。既有耦合：`src/core/constants/cards.ts` 的字數上限在 `tools/validate/cards.mjs` 有第二份；新模式不要再加第三份，要不要順手解掉由你提案。
8. 有感的改版要在 `src/core/constants/changelog.ts` 加一則。

## 成品

- 拆包表：每包的範圍、建議執行者（定調與美術由主席自己做；可拆、有明確驗收的才派 agy Neon／Sonnet 子代理）、驗收指令（要能由流水線跑，例：`npm test`、`npm run lint`、`npm run build`、看圖腳本）

## 什麼時候停下來問
- 讀完覺得「四格漫畫」這個方向本身不適合某類卡（例如純數字表），直接在開案書寫你的替代做法，不要硬塞四格。
- 需要使用者決定的事（例如美術方向二選一、要不要鬆綁不新寫題目），列在開案書的「待使用者決定」一節，不要自己定。

## 固定三條
- 只結束自己啟動的行程。
- 不為了過檢查改造形或改驗收。
- 不新增耦合。

## 回報
完成後回報：開案書路徑、切線摘要（各幾張卡、幾包）、待使用者決定的清單。每個結論附產生它的指令或檔案位置。
