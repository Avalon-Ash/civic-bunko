# 派工單 P2b：內容加工（口訣、陷阱、圖、逐選項說明）

無人值守。讀完本檔與必讀檔案後直接動手，不要寫計畫、不要等確認。
**這份派工單每批重複使用**：這一批要加工的試卷由啟動提示指定（`PaperId`）。

- **目標**：讓一位零法學基礎、靠圖像與口訣學習的考生，答完一題後 5 秒內看懂「為什麼」。每題產出：一句口訣、一句陷阱提醒、一張小圖、四個選項各一句說明。
- **模型與強度**：`gemini-4-hydrogen-high`
- **工作區**：啟動提示指定的資料夾。只准改這個資料夾內的檔案。

## 成品

`data/enrich/<PaperId>.json`（只新增這一個檔）：

```json
{
  "paperId": "115-general-admin-law",
  "model": "gemini-4-hydrogen-high",
  "generatedAt": "ISO 時間",
  "items": [
    {
      "id": "115-general-admin-law-q08",
      "topic": ["admin-law/rules"],
      "mnemonic": "要罰人，先問中央。有罰則就是「核定」。",
      "trap": "備查是做完才告知，不是事前。",
      "plain": "市議會通過「亂丟垃圾要罰錢」的規定。發布前要先送中央做什麼？",
      "marks": [
        { "text": "自治條例", "color": "blue" },
        { "text": "處罰規定", "color": "blue" },
        { "text": "事前", "color": "blue" }
      ],
      "options": {
        "A": { "why": "備查＝事後告知。沒有罰則才用這個。", "lawRef": { "law": "地方制度法", "article": "26" } },
        "B": { "why": "特許不是自治法規的監督方式。", "lawRef": null },
        "C": { "why": "有罰則 → 先報中央核定，再發布。", "lawRef": { "law": "地方制度法", "article": "26" } },
        "D": { "why": "法條沒有「通報」這種監督方式。", "lawRef": null }
      },
      "visual": {
        "kind": "flow",
        "lanes": [
          { "steps": [ { "text": "有罰則", "tone": "hot" }, { "text": "核定", "tone": "key" }, { "text": "發布", "tone": "plain" } ] },
          { "steps": [ { "text": "沒罰則", "tone": "plain" }, { "text": "發布", "tone": "plain" }, { "text": "備查", "tone": "plain" } ] }
```

另一種圖 `versus`（兩邊對比）：

```json
{ "kind": "versus",
  "left":  { "title": "撤銷", "points": ["處分本來就違法", "知道後 2 年內"] },
  "right": { "title": "廢止", "points": ["處分本來合法", "原因發生後 2 年內"] } }
```

## 每個欄位怎麼寫

- **`mnemonic`（口訣，≤ 40 字）**：像朋友講的一句話，要能唸出來、有畫面。寫「結論＋怎麼記」，不寫「依某法第幾條規定」。好：「要把人帶走，法官先點頭。」壞：「依行政執行法第 17 條，拘提須經法院裁定。」
  口訣只講「這題的正解」那一個重點，不要把四個選項的知識全塞進去；其他選項的重點留給各自的 `why`。
- **`trap`（陷阱，≤ 30 字）**：這題最容易錯在哪。好：「看到『僅限』『只有』，多半是錯的。」
- **`plain`（白話情境，≤ 60 字或 `null`）**：把題目改成生活場景的問句。英文題、國文題、純記憶題填 `null`。
- **`marks`**：`text` 必須是題幹裡**一字不差的原文片段**。紅色只標反向問法（何者錯誤、非屬、不包括…），有反向問法就一定要標；藍色標法條名或核心名詞，最多 3 個。
- **`options.<A–D>.why`（≤ 50 字）**：這個選項為什麼對或錯，直接講原因。反向題要講清楚「這句本身是對的」還是「這句錯在哪」。
- **`lawRef`**：只有在 `data/laws/` 裡**實際查到**那一條、而且條文內容確實支持你的說明時才填；`law` 用 `data/laws/index.json` 裡的法規名稱，`article` 是條號字串（例 `"26"`、`"17-1"`）。查不到、不確定、或依據是釋字／學理／施行細則，一律填 `null`。**不准憑印象寫條號。**
- **`visual`**：能畫就畫，優先選最能幫助記憶的那種；真的沒有適合的圖才填 `null`。`flow` 用在流程、因果、分類（1–3 列，每列 2–4 步，每步 ≤ 12 字；`tone`：`hot`＝條件或陷阱、`key`＝要記的答案、`plain`＝其他）。`versus` 用在兩個容易混淆的概念（標題 ≤ 10 字，每邊 1–3 點，每點 ≤ 16 字）。
- **`topic`**：從 `data/topics.json` 選 1–2 個屬於本科的 `id`。
- **`lawChanged`（≤ 80 字或 `null`）**：對照 `data/laws/` 的現行條文，如果這題的官方答案或題目前提已經和現行法不同，寫「現行規定是…」；一致就填 `null`。這是重點檢查項：`data/laws/index.json` 列有每部法的修正日期，考試年度早於修正日期的要特別對照。
- **`confidence`**：你對說明有把握（有條文可對，或是確定的基本概念）填 `high`；沒有條文可對又不確定填 `low`。**寧可老實填 `low`，不要編理由。**
- **`reviewed`**：一律 `false`。

## 必須遵守

- 答案以 `data/official/<PaperId>.json` 的 `answer` 為準，不得質疑或更改；有 `correction` 的題目，說明要提到官方更正。
- 不得修改 `data/official/**`、`data/laws/**`、`data/topics.json`。
- 行政法、地方自治、法學知識的法律題：寫每一題之前，先在 `data/laws/` 查相關條文再下筆。
- 用繁體中文、臺灣用語；不用簡體字、不用艱澀術語解釋術語。
- 每題都要有四個選項的 `why`；整份試卷每一題都要加工，不可跳題。

## 驗收指令（只能跑這一個；字串照抄，單獨一次呼叫）

```
node tools/validate/enrich.mjs
```

及格：退出碼 0、`ERROR=0`。字數超過就改寫得更短，不是刪內容；驗收腳本不准改。

## 什麼時候停下來

- 同一個驗收錯誤修兩次仍在：停下回報。
- 發現官方答案看起來和現行法衝突：不要改答案，照規定寫進 `lawChanged`，並在回報裡列出題號。

## 回報格式

照 `AGENTS.md` §6。另外列出：`confidence: low` 的題號、`lawChanged` 不是 `null` 的題號與內容、`lawRef` 為 `null` 的選項數、驗收指令最後一行輸出。
