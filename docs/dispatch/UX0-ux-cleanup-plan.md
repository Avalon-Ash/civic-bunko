# UX0：UI／UX 整理 開案（交 Fable）

## 目標
替 civic-bunko 開一份 UI／UX 整理的開案書，寫到 `docs/plans/ux-cleanup.md`，並和四格漫畫的開案書 `docs/plans/comic-cards.md` 排進同一份時程。只寫開案書，不寫程式。

## 真正的需求
使用者原話與主代理的量測都在 `docs/reference/ux-audit-2026-11-26.md`，先讀完。三件事：
1. **任務引導**：沒有正確引導到要按的按鈕。已找到一個實例：今日頁的「今日任務」卡一律導到小貓分頁。「任務」這個詞有三套。請把她在 App 裡所有「被叫去做某件事」的地方都列出來（任務、成就、每日關卡、提示、更新紀錄、空狀態的說明…），逐一判斷點下去會不會到能完成它的那顆按鈕。
2. **全部攤開**：功能都在，不是不好，但排版亂。
3. **滑動太長**：圖卡 5.7 個螢幕、小貓 5.5 個螢幕，刷題的「開始」在最底。

## 限制
1. **時間**：今天 11-27，12-02 起只修錯，考試 12-05。整理和漫畫搶同樣的 5 天。請在兩份開案書之上給**合併時程**：哪些 UX 包先做、哪些和漫畫並行、哪些排到考後；理由寫出來。「她今天刷得到題」優先。
2. **不砍功能、不換她熟悉的位置太多**：她已經在用。可以收合、分層、換順序、把設定集中；搬動主要入口（底部分頁、開始刷）要寫理由。
3. **她的資料不能壞**（`AGENTS.md` §2、golden 測試）。收合狀態之類的新設定只存本機、選填。
4. **介面規則先查**：`AGENTS.md` 的介面規則、ADR 0006（不用瀏覽器彈窗、介面堆疊最小）、`docs/plans/civic-bunko.md`、`docs/plans/cat-wardrobe.md`、`docs/plans/cat-house.md`（小貓頁的設計來由）。新元件優先沿用 `src/ui/kit/`。
5. **和漫畫的交集**：圖卡頁的列表、卡片抽屜兩份都會動，請講清楚誰先、誰改哪個檔，不要讓兩個執行者改同一檔。
6. **驗收要能量**：例如各分頁在 390×844 的捲動高度上限、從今日頁到每種任務的完成按鈕要點幾下。量法要能由腳本或主席在預覽裡重跑。
7. 你看不到畫面截圖；需要看實際長相時，在開案書裡寫「主席要截哪幾張」作為第一包的前置，不要憑猜決定視覺細節。

## 成品
`docs/plans/ux-cleanup.md`：
- 問題清單（每條附出處：檔案:行或量測）
- 資訊架構：每個分頁放什麼、什麼收合、設定集中到哪裡；改前改後對照
- 任務引導：統一「任務」的叫法與點了去哪裡（只定義在一處，例如一張「任務 → 目的地」的表）
- 拆包表（每包範圍、執行者、驗收指令）
- 合併時程（UX＋漫畫，11-27 到 12-01，以及考後）
- 待使用者決定、什麼時候停下來問

同時更新 `docs/plans/comic-cards.md` 的 §6、§7（時程與拆包）讓兩份一致；其他節不動。

## 固定三條
- 只結束自己啟動的行程。
- 不為了過檢查改造形或改驗收。
- 不新增耦合。

## 回報
開案書路徑、合併時程表、待使用者決定清單；每個結論附出處。
